# Contribution Guide

This guide outlines the process for contributing to the Stoat project.

## Repository Lifecycle

### Committing Changes
- **Commit Sign-off**: Please sign-off your commits (refer to [Git flag](https://git-scm.com/docs/git-commit#Documentation/git-commit.txt---signoff) and [DCO obligations](https://developercertificate.org/)).
- **Commit Signatures**: Sign commits where possible [here](https://docs.github.com/en/authentication/managing-commit-signature-verification/signing-commits).
- **Commit Style**: We prefer the **Conventional Commit** style.
- **Format Tools**: Use formatters like `prettier` or `cargo fmt` when they are present in the project.
- **PR Scope**: Try to keep each Pull Request focused on a single feature or change to prevent conflicts.

### Pull Request Workflow
- **Titles**: All PR titles must follow the [Conventional Commit style](https://www.conventionalcommits.org/en/v1.0.0-beta.2/) and will be squash merged.
- **Generative AI**: Do not open PRs generated by Large Language Models.

## Seeking Help & Project Guidance

### Where to Ask Questions
- **Current Development**: For immediate questions, please consult the development server: `https://stt.gg/API`.
- **Issue Tracker**: Check repo issues for `help wanted` labels.
- **Project Board**:
    1. **Newcomers/General Help**: Refer to ["What can I help with?"](https://github.com/orgs/stoatchat/projects).
    2. **Free Issues**: Issues anyone can tackle.
    3. **Todo Issues**: Issues suitable for experienced developers, but please ask before starting as they can be complex.
    4. **Feature Suggestions**: For new ideas or feature requests, use [Feature Suggestions](https://github.com/orgs/stoatchat/discussions/new?category=feature-suggestions).
- **Future Work**: Avoid working on issues marked as "Future Work" or those outside the current milestone.
